# AIROOM Native — 多 AI 直播與協作功能版（開發版本）

以先前 **AIROOMNative_QuotaRestore** 為基礎，優先補齊原版缺少的三類流程，並依使用者需求把「自動閒聊」延伸成長時間的**雙 AI 同台直播**。

## Mac 上安裝／測試

1. **先退出舊版並備份** `~/Library/Application Support/AIROOMNative`，不要刪除 Keychain 項目。
2. 在 Mac 的 Codex App 以 **Local** 開啟本 ZIP 解壓後的資料夾。
3. 在 `macos/` 目錄執行：

```bash
swift test
./Scripts/package-app.sh
./Scripts/install-app.sh --open
```

`install-app.sh` 會先結束執行中的 AIROOM，把 `/Applications` 裡的舊版**移到垃圾桶**（檔名附版本號與時間，可還原），再安裝新版。版本號（`CFBundleVersion`）等於 git commit 數，`AIROOMGitCommit` 記錄對應的 commit。資料與 Keychain 不受影響。

封裝腳本會檢查原版圖片；缺少時從固定上游 Commit 下載並驗證，必要時會使用網路。產生的 `.app` 為本機開發用途臨時簽章，未經 Apple 公證。請先驗證新版讀取原有資料正確，再將 App 取代 `/Applications` 的舊版；**不要刪除 Application Support 或 Keychain**。

## 新增：人物卡裁切編輯器

在「管理人物卡」選擇人物 →「調整頭像」，即可拖曳、縮放、預覽並儲存；不會修改原版立繪。詳見 `AVATAR_EDITOR.md`。

## 新功能入口

- **茶歇室 →「雙 AI 同台直播模式」**：選兩位在場成員，輸入主題，設定發言間隔、輪數、時長；按「開始雙 AI 同台直播」。過程中可插入觀眾暱稱和留言，下一輪 AI 會讀到；按「停止直播」終止當前程序。
- **左側「排程與直播」**：新增每日提醒或向共用對話室發送指定訊息，並可設定低頻自動閒聊的每日上限。排程僅在 App 開啟期間觸發，未執行時不補發。
- **圓桌 → 歷史議題**：兩份獨立完成的答案可啟動交叉互評與非約束性投票，最後由使用者手動「採用」候選，再將結果帶回尚可編輯的專案。
- **專案工作區 → 新建立的專案**：討論 → 選負責人 → 產生方案 → 人工核准後在副本執行 → Claude 唯讀審查與人工驗收 → 完成。舊版建立的簡化專案保留舊流程。

## 直播安全與預算保護

- 直播必須**手動開始**；退出 App 後不會自動恢復，沒有隱性背景連線。
- 至少兩名啟用成員。發言間隔 **15–180 秒**、輪數 **2–300 輪**、每場最長 **10–240 分鐘**；預設 45 秒／80 輪／120 分鐘。每一輪都可能觸發供應商額度消耗。
- 收到官方近期且明確的 100% 配額樣本就暫停；沒有額度資料不代表無限額度，請自行監看。
- 僅**成功完成**的 AI 發言可傳給下一位；遇到失敗、取消或 CLI 未確認的回覆即中止連續對話。
- 每 12 輪嘗試產生一次長期摘要；摘要失敗不覆蓋舊摘要，完整紀錄仍在本機加密資料中。摘要是模型產生的，可能忽略或誤述內容。
- 插入觀眾留言目前僅是**手動文字輸入**；尚未串接 Twitch／YouTube 聊天室、OBS、TTS、Live2D、音訊播出或彈幕審核。
- 外部 Claude／Codex 程序仍能以你的本機使用者權限執行；工作副本過濾不是 OS 核心層沙箱。

## 驗證界線

- Linux 上執行 Foundation 核心測試與所有 SwiftUI 檔案的 Swift 語法解析。
- **尚未**在 Apple Silicon Mac 上做新版完整編譯、真實帳號連續數小時直播、TTS／OBS 串接或實際付費額度測試。
- 六階段是**序列式雙 Agent MVP**，非原版完整的多工作項平行派工／重試排程引擎。詳見 `FEATURE_PARITY.md`。
